# 07. 재구성 설계도 — 오픈소스 부품으로 "ChemDraw급" 제품 만들기

> 기준일 2026-11-10. 앞 문서들의 분해 결과([03](03-chemdraw-functional-decomposition.md) 블록, [05](05-engine-teardown-rea.md) 실측, [06](06-capability-matrix.md) 매트릭스)를 *재조립 계획*으로 바꾼 문서다. ChemDraw의 코드나 상표, UI를 복제하는 것이 아니다. **같은 기능 블록을 공개 라이선스 부품으로 독자 구현하는 설계**다.
>
> 라이선스 주의: Ketcher/Indigo(Apache-2.0), RDKit·OpenChemLib·JSME·Revvity CDX 코드(BSD-3), OPSIN(MIT), ChemDoodle Web(GPLv3 또는 상용, 이 설계에서는 제외).

## 1. 목표 아키텍처

```

│ 장면 모델: CDX 객체 모델과 1:1인 TS 타입(52 객체·400 속성) ── 04 §3, cdx_tags.json에서 코드 생성        │
```

## 2. 핵심 결정과 근거

| 결정      | 선택                                                                                           | 근거(이 분해에서 확인한 사실)                                                                                                             |
| --------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 문서 모델 | **CDX 객체 모델을 내부 모델로 채택**(KET 아님)                                                 | ChemDraw 락인의 핵심은 파일·Office 임베딩이다(03 §5). 속성 80%가 비화학 정보라서, KET 같은 축소 모델로는 왕복 시 정보가 손실된다(04 §2.2) |
| CDX I/O   | Revvity BSD-3 C++ 코드를 WASM으로 빌드해 정본 파서로 사용, `cdx_dump.py`는 테스트 오라클       | 실제 ChemDraw 출처의 코드이며 CDX/CDXML 이중 직렬화를 제공한다(04 §3). Unknown 객체 보존으로 상위 버전 파일도 안전하다                    |
| 화학 커널 | RDKit MinimalLib 1순위, Indigo 대안                                                            | RDKit은 descriptors, fingerprints, MCS, R-group 분해, PNG 메타데이터 삽입을 지원한다(05 §2.2). Indigo는 CDX와 HELM 변환에 강하다(05 §2.1) |
| 커널 경계 | Web Worker + 메시지 계약(Ketcher `Command` enum 방식)                                          | UI 프리즈 방지, 커널 교체 가능성(05 §2.1)                                                                                                 |
| 바이오    | Ketcher Macromolecules 엔티티 체계 참고 + CDX `Monomer` 노드로 직렬화                          | 두 설계의 차이(04 §4)를 브리지로 흡수                                                                                                     |
| Office    | 1단계: PPTX/DOCX 속 OLE `CONTENTS`에서 CDX를 읽고 쓰기 → 2단계: Office.js 애드인으로 삽입·갱신 | Ketcher의 PPTX 추출 경로가 실증한 방식이다(05 §2.1). in-place OLE 서버(Windows COM)는 후순위                                              |

## 4. 위험

- **법적**: CDX 포맷 상호운용은 공개 SDK와 BSD 코드에 근거하므로 위험이 낮다. 다만 ChemDraw 이름·아이콘·UI 트레이드 드레스는 사용하지 않는다. "ChemDraw" 상표는 *호환성 설명*에만 쓴다.
- **기술**: CDX 그래픽(스펙트럼, 플라스미드, TLC) 렌더링 충실도. 구 Mac 빅엔디언 파일, 임베디드 EMF/PNG는 `cdx_dump.py`로 검증하지 않은 영역이다(04 §6).
- **시장**: Revvity가 ChemDraw와 ACD/Labs를 모두 가지면서 명명·NMR 해자가 깊어졌다. 정면 경쟁보다 G1–G12 공백(02 §4.1)과 Marvin JS EOL 창(~2027-12)을 노리는 편이 현실적이다.
